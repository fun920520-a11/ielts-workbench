# Obsidian → 雅思备考工作台 同步器

## 为什么需要它

工作台是**托管在资料库的网页**，浏览器出于安全限制**读不到本机磁盘**，所以网页本身无法直接打开 `D:\学习笔记\灵感笔记\09 英语学习\*.md`。这个文件夹里的 Python 程序就是「本机读文件 ↔ 网页取数据」之间的桥。

```
Obsidian 两份 .md  ──(解析)──>  本地同步桥 http://127.0.0.1:8787  ──(fetch)──>  工作台页面
                                        │
                                        └─ 页面拿到数据后，顺手写一份快照进资料库表
                                           （手机/其他电脑打开时读这份快照）
```

## 日常怎么用

1. 双击 **桌面的 `雅思工作台-双击启动同步桥.bat`**（或本目录的 `启动同步桥.bat`）——
   会弹一个黑窗口，**别关**，里面应看到：
   ```
   [1/3] Python: ...\python.exe
   [2/3] Port: 8787
   [3/3] Starting...
   [..] 同步桥已启动: http://127.0.0.1:8787
   ```
   同时浏览器自动打开 **本机直连版** `http://127.0.0.1:8787/`。
2. 在 Obsidian 里改完笔记、保存。
3. 回工作台点 **「🔄 同步 Obsidian」**（侧栏、单词本、听力页都有）。
4. 看到「✅ 已同步 240 词 / 1 集」就完成了。

### 两种打开方式（v8 起）

| 打开方式 | 地址 | 说明 |
|---|---|---|
| **本机直连版**（推荐，启动器默认打开） | `http://127.0.0.1:8787/` | 页面由同步桥自己提供，**与接口同源，浏览器绝不拦截**；Obsidian 数据即点即得 |
| 在线版（资料库托管） | `https://www.workbuddy.cn/space/d/h9BN0kNcLlrkdqkuzvaRf5` | 手机/其他设备用；电脑上**在系统 Chrome 打开**时也能连桥；**在 WorkBuddy 应用内打开时连不上**（内嵌浏览器禁止访问本机，无弹窗、无法授权） |

> **第一次用直连版要做一次数据搬家**（30 秒）：打开旧在线版 → 「📊 数据统计」→「⬇️ 导出 JSON 备份」→ 打开直连版 → 「📊 数据统计」→「⬆️ 导入恢复」。
> 原因：打卡/记录等存在浏览器 localStorage，**按网址隔离**，`workbuddy.cn` 和 `127.0.0.1:8787` 是两个独立的存储空间。
> 在线版的「单词掌握状态在线表」在直连版里不可写（无登录态），其余功能全部可用。

**怎么一眼确认连上了**：侧栏最底部有一行灰字

```
构建 v8 · 桥 127.0.0.1:8787 · 词表 240 词
```

- 直连版里这行永远显示当前地址，且数据即点即得；
- 在线版里桥地址显示成 `127.0.0.1:8787`（或 `:8800`）说明页面找到了桥；
- 在线版里**始终连不上**且你是在 WorkBuddy 应用内看的 → 不是故障，是内嵌浏览器限制，改用直连版。

> 黑窗口开着的 10 秒内，页面会自己探到桥并自动同步一次，**不点按钮也能连上**。
> 关掉黑窗口 = 停止同步。工作台会自动退回「🔵 离线快照」，已同步的内容照常看，只是点同步会提示连不上。

## 三层数据保障（为什么打开一定不是空的）

| 优先级 | 数据层 | 说明 |
|---|---|---|
| 1 | 🟢 本地同步桥 | 桥开着，点「🔄 同步 Obsidian」拉笔记最新内容 |
| 2 | 🔵 资料库快照 | 桥关着，但有网 → 读最后一次同步写进表的快照 |
| 3 | 🟡 内置快照 | 桥关着 + 表也读不到 → 用页面打包时内嵌的那份（打开即完整 240 词） |

所以**桥不通也不会缺词**，只是内容停在打包那天。「📥 导入 data.json」是第四条路：把本目录的 `data.json` 直接喂给页面。


抓的列：单词 / 音标 / 词性 / 中文 / 语块示例 / 记忆法 / 组别 / 主题 / ⚠️待巩固。
听力抓：标题、播出、话题、主持人、嘉宾、中英对照逐句、本周问题+选项+答案、重点词汇、6 句摘句、断句谱。

**同步规则**：对两份文件算 sha256 指纹，指纹没变就不重写（控制台会打「内容未变，跳过写入」）；`--force` 可强制重算。

## 命令

```bash
python obsidian_sync.py serve            # 起桥（bat 就是这条 + 自动开浏览器）
python obsidian_sync.py once             # 只解析一次，写 data.json
python obsidian_sync.py once --force     # 强制重算
python obsidian_sync.py status           # 看上次同步时间/词数/集数
```

接口：

- 同步：`/api/ping` `/api/status` `/api/sync` `/api/data`
- 本地 ASR（听力页用）：`/api/asr/status` `/api/asr/list` `/api/asr/upload`（POST 裸二进制）
  `/api/asr/jobs`（POST 建任务 / GET 轮询）`/api/asr/cues`（GET 取字幕 / POST 存字幕）
  `/api/asr/audio`（GET，支持 Range）`/api/asr/del`

## 本地音频精听（v13 起）

听力页新增一整块：**导入音频 → 本地 ASR 出带时间轴的英文字幕 → 粘贴中文按句匹配 → 点句跳播**。
它和「同步 Obsidian」共用同一个桥、同一个端口，没有第二个窗口要开。

> **入口要说清**：这块功能只能在**本机直连版** `http://127.0.0.1:8787/` 里用。
> 在线版（`https://www.workbuddy.cn/...`）是 https 源，浏览器会把「https 页面 → 127.0.0.1」的请求
> **静默挂起**（不报错、只转圈），所以在线版里精听永远是灰的。v13.1 起卡片会自己说清这点，
> 并给一个「🖥 打开本机直连版」按钮，点一下换过去就行 —— 桥、音频、字幕都是同一份。

### 三步怎么走

1. **导入音频**：选本机 mp3/m4a/wav/ogg/flac（≤300MB）。文件会被存到 `obsidian-sync/audio/`
   （文件名是内容 sha1 前 16 位，同一个文件重复导入不会存两份），页面里可以随时从「本机音频库」重新打开。
2. **生成英文字幕**：点「🎙 开始识别」→ 本地 faster-whisper 转写（词级时间戳，所以句子首尾落在真实词边界上）。
   第一次会下载模型（约 145MB，官方源不通会自动走 `hf-mirror.com`，有百分比进度 + 「已等 N 分 N 秒」）。
3. **粘贴中文翻译**：一行一句，句数**不必**和英文相同；点「🔗 按句子顺序匹配」按长度比例铺到时间轴上：
   - 中文句数 = 英文句数 → 一一对应
   - 中文多 → 按比例合并进同一句英文
   - 中文少 → 一句中文覆盖连续几句英文，只在首句显示
   匹配完每行的中文都能**点一下直接改**（自动存回桥）。

### 为什么要「按句匹配」而不是直接对齐行号

ASR 出来的句子边界是由标点和停顿决定的，和你翻译时断句的位置几乎不可能完全一致。
硬按行号对齐，从第 3 句开始就会整体错位。所以这里按**长度比例**分配：一句英文的字符越多，
它占用的中文句数就越多，错位只发生在一句之内，不会累积。

### 播放器行为

- 点任意一句 → 跳到该句起点并继续播（`currentTime = cue.st`）
- 当前句高亮 + 自动滚动跟随；**单句循环**到句尾自动回跳，精听磨一句很好用
- 倍速 0.6–1.2×、上一句/下一句、中英/仅英/仅中、**盲听**（英文模糊，先听后看）
- 导出 `.srt`（含中英两行）

### 依赖与降级

- 需要 `.venv` 里的 faster-whisper：`start-bridge.bat` 会优先选它；
  没有就自动退回同步模式（同步照常，只是识别按钮会提示去装）。
- 模型目录优先复用 `podcast-bridge/models/`，其次 `obsidian-sync/models/`，**不会重复下 145MB**。
- 想要更准：新建 `obsidian-sync/asr-config.json`：

```json
{ "model": "small.en", "device": "cpu", "compute_type": "int8", "beam_size": 5,
  "hf_endpoint": "https://hf-mirror.com" }
```

### ⚠️ 改了 `asr_core.py` / `obsidian_sync.py` 必须重启桥

Python 只在任务开始时导入一次模块。桥开着的时候改代码，跑的还是旧逻辑 —— 这个坑已经踩过一次
（旧进程把 0 词写进了缓存）。重启 = 关掉黑窗口再双击 `启动同步桥.bat`。

例外是**数据**：`data.json` 被外部重写（改时间变了）时桥会自动重新载入，不用重启（v15 起）。
只有 `.py` 代码才需要重启。

### 短文从哪来（2026-10-25 起：以 Obsidian 为准）

组 12 起，短文的**真源在笔记里**，不再写进页面。在「每日词汇/第NN-NN组.md」的组区块内放这几节：

```
### 📖 学以致用 · 30 词短文

#### {标题}（{N} words）

{英文正文，目标词用 **加粗**，空行分段}

#### 中文对照

{中文}

#### 🪝 记忆钩子

{一句话钩子}

**覆盖核对**：30 / 30 ✅
```

然后点页面上的「🔄 同步 Obsidian」，短文自动出现 —— **不用改 HTML、不用重新打包**。

解析器认这些规则（`obsidian_parse.parse_passages`）：

- 三级标题里必须含「**30 词短文**」字样，所以早期只有「5 个句子」的组不会被误抓
- 第一个 `#### ` 当标题，末尾的「（183 words）」自动去掉
- `#### 中文对照` 和 `#### 🪝 记忆钩子` 之间分别是中英正文
- 引用块（`>`）、「覆盖核对」行、`**` 星号都会清掉；空行分段保留
- 正文短于 80 字符视为半成品，直接跳过（宁可没有，也不要塞半篇）

优先级：**页面里手改的（`DB.passages`）> 同步来的 > 内置 seed**。
同步结果单独存 `localStorage: ielts_passages_sync_v1`，不进 DB —— 所以「重新同步」不会冲掉手改的，
「清空数据」也不会把笔记里的短文一起清掉。

### 朗读：暂停 / 恢复 + 跟随（v17 起）

工具条右侧的「🔊 朗读英文」是**分段朗读**：按空行把正文切成一段一段，逐段送进浏览器语音引擎。
这样才知道"现在读到哪一段"，也顺手绕开 Chrome「一段太长会被中途掐断」的老毛病。

| 按钮 | 什么时候出现 | 作用 |
|---|---|---|
| 🔊 朗读英文 | 未播放 | 从第一段开始，读到哪高亮哪 |
| ⏸ 暂停 / ▶️ 继续 | 播放中 / 暂停中 | 同一个按钮切换，暂停不丢进度，继续时接着读 |
| ⏹ 停止 | 播放 / 暂停时 | 回到起点，清掉高亮 |
| 🎯 跟随朗读 | 常驻（默认开） | 关掉后只高亮不滚动，方便自己滚着看 |

跟随的规则：当前段落加浅蓝底 + 左侧蓝条；**段落已完整落在可视区时不滚动**（否则每段都晃一下很烦），
只有读到的段落跑出屏幕才平滑滚上来，停在视口上方约 26% 的位置。滚不到位的兜底是在 460ms 后硬定位一次。

几个边界：

- 「只看中文」时滚的是**中文段**，中英段落数不一致就按长度比例对应（英文 5 段 / 中文 4 段 → 第 2 段对第 2 段）
- 双语模式下当前英文段和对应中文段**一起高亮**
- 切换组次、离开短文页、点词表里的 🔊 —— 都会先停掉短文朗读，避免声音还在响却找不到暂停键
- 暂停后某些浏览器会把当前段静默掐掉（`resume()` 没声音）→ 恢复时检查一次，没声音就重读当前段，不跳段

回归测试：`node test-pspeak.js`（77 条：分段、首段高亮、逐段推进、暂停不推进、恢复不重读、掐断兜底、
读完收尾、停止清高亮、按钮三态、跟随开关、只看中文的比例映射、切组/切页/单词发音打断、错误容错）。

## 排错

| 现象 | 原因 / 处理 |
|---|---|
| 黑窗口出现「内容未变（指纹 xxx）—— 笔记没改动，数据已是最新」 | **不是报错**。笔记 sha256 没变，所以跳过重写缓存，数据照样能同步。改了笔记再点同步就会看到「同步完成」 |
| 在 WorkBuddy 应用内打开在线版，同步/测试连接始终失败 | **预期限制**：内嵌浏览器禁止公网页面访问本机端口。双击启动器改用本机直连版 `http://127.0.0.1:8787/`（首次需导出/导入搬一次数据） |
| 在系统 Chrome 打开在线版，提示连不上 | 看地址栏左侧权限图标，把「本地网络访问」设为允许后刷新；仍不行就用直连版 |
| 点同步提示「连不上本地同步桥」 | 黑窗口没开或已关；重开启动器，再点页面里的「🩺 测试连接」（会同时探 8787 和 8800，探到即自动记住） |
| 黑窗口闪一下就没了 | 没找到可用 Python（双击只弹应用商店就是这个）。装真 Python 3 并勾 Add to PATH |
| 端口被占 | 启动器自动换 8800；页面会自动探测并记住新地址，**不用手改** |
| 同步成功但词没变 | 检查是不是存到了「阶段1」以外的文件；词表只认 `雅思备考·阶段1 基础重建期.md` |
| 手机打开是旧内容 | 手机读的是资料库快照，需要在电脑上点过一次同步 |
| 页面还是旧版 | 强制刷新：`Ctrl+F5`（或手机上清一下站点缓存） |
| 识别按钮报「没装语音识别引擎」 | 双击 `podcast-bridge/install-asr.bat` 装一次（自带独立环境），重启桥 |
| 识别一直卡在「已等 N 分」 | 多半在下载模型：看黑窗口有没有 `[asr]` 日志。国内直连 huggingface.co 会超时，已在代码里自动切镜像 |
| 中文匹配后有几行没有中文 | 中文句数少于英文句数，按设计只在首句显示；点那一行的「（点这里补中文）」手动补 |
| 桥重启后任务查不到 | 任务只存在内存里（`JOBS`）。重新点一次「🎙 开始识别」即可，字幕本身是落盘的，不会丢 |
| 精听卡片一直「正在检查本机桥…」，既没连上也不报错 | 十有八九是**在在线版（https）里点的**。https 页面访问 127.0.0.1 会被浏览器静默挂起。v13.1 起 2.2 秒就会说明原因并给按钮 → 点「🖥 打开本机直连版」换到 `http://127.0.0.1:8787/`。若直连版也这样，就是桥窗口关了（重开启动器），或端口不是 8787（页面会自动扫 8787/8800/8899） |
| 没连上时点了「选择音频」 | 文件不会丢：页面会先记住它，桥一连上就自动上传（v13.1） |
| 笔记里加了新组，页面上还是旧的（少一组/少几十词） | v15 起桥会看 `data.json` 的修改时间，外部重写过就**自动重新载入**，不用重启桥；要立刻生效点一次「🔄 同步 Obsidian」。仍然旧的话 `Ctrl+F5` 强刷页面 |

> ⚠️ **`启动同步桥.bat` 必须保持纯 ASCII**。Windows 的 cmd 按系统 ANSI 编码解析 .bat，写成 UTF-8 中文会把命令拆坏（表现为「黑窗口一闪而过」或报一堆乱码命令）。中文提示一律放在 Python 里输出（已 `chcp 65001`）。

## 文件

- `start-bridge.bat` — 真正的启动器（纯 ASCII，避免 cmd 编码坑）
- `启动同步桥.bat` — 中文名转发入口，内容只有一行 `call start-bridge.bat`
- `obsidian_parse.py` — 解析两份笔记（纯标准库）；含「复习排期」解析（排期表行 + 各组「当日复习任务」行 → `reviewPlan`）
- `obsidian_sync.py` — 本地桥 + 同步逻辑 + HTTP 服务 + 同源直连版页面（`http://127.0.0.1:8787/`）
- `inject_seed.py` — 把 data.json 重新注入页面内置快照（`<script id="obs-seed">`），改完页面结构后跑一次
- `smoke-page.js` — 无头冒烟：`USE_BRIDGE=1 node smoke-page.js` 验跨源、`LOCAL=1` 验同源直连、不带变量验兜底
- `test-groups.js` — 复习分组弹窗/保存/过滤回归（冻结日期到 2026-10-17）：`node test-groups.js`
- `test-scope.js` — **学习范围硬边界 + 组次徽标**回归（冻结日期到 2026-10-19）：选第 9 组 → 队列 30 词全是第 9 组、干扰项不越界、单词本每行带「第 N 组」
- `test-speak.js` — 口语模块 + 评分算法回归：`node test-speak.js`
- `asr_core.py` — 本地 ASR 内核（模型复用/下载、词级切句、幻觉过滤），可单独跑：`python asr_core.py 音频.mp3`
- `test-audio.js` — 精听模块回归（50 断言）：中文三种句数关系的匹配、时间查找、点句跳播、SRT、DOM id
- `test-audio-e2e.js` — 页面 × 真实桥端到端（22 断言）：先起桥，再 `node test-audio-e2e.js`
- `audio/` — 导入的音频 + 每条的 `字幕.json`（含中文）
- `snap_v12.json` — 最近一次资料库快照行更新载荷（历史参考）
- `data.json` — 最近一次解析结果（缓存，可删，会自动重建；也是「📥 导入 data.json」的输入）
